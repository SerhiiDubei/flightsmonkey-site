# Flights Monkey v7 — запуск, API-ключі, розгортання

Цей файл відповідає на два питання: **куди вписати API-ключ** і **як розгорнути**.
Технічний опис самого коду — у `README.md`.

Потрібен **Node.js 18 або новіший** (перевірено на 24.x).

---

## 1. Швидкий старт (без жодного ключа)

```bash
npm install
cp .env.example .env
npm start
```

Відкрити http://localhost:3000

За замовчуванням `FLIGHT_PROVIDER=mock` — сайт генерує вигадані рейси. Працює
все: пошук, фільтри, сортування, «Load More», сторінка бронювання, підтвердження.
Ключі для цього не потрібні. Це нормальний режим для демо та розробки.

## 2. Куди саме вписувати API-ключ

### Локально

Ключ живе **тільки** у файлі `.env` у корені проєкту, поряд із `package.json`.

```
xtremefares-clone/
├── .env            ← ось сюди
├── .env.example    ← шаблон, з якого копіюєте
├── package.json
├── server.js
└── src/
```

Файл `.env` у `.gitignore` і в `.vercelignore`, тому він **не потрапляє ні в git,
ні в деплой**. Це навмисно.

Створити його:

```bash
cp .env.example .env
```

Далі відкрити `.env` і змінити два рядки. Перший каже, який постачальник
відповідає на пошук, другий — сам ключ.

### Варіант A — Wikiproject, консолідатор клієнта (ЦЕ ТОЙ, ЩО ПОТРІБЕН)

Це API, яке надав клієнт, і саме воно має працювати в продакшені. Duffel від
якого ми починали, **відпав за рішенням по вартості** — лишаємо адаптер у коді,
але підключати його не треба.

Перевірено на живому ендпоінті 23.09.2026: 700 оферів на переліт MSP–CLT
туди-назад за 1.8 с, усі чотири класи обслуговування віддають різні тарифи,
валюта перераховується на боці постачальника.

У `.env` треба чотири значення — їх видає постачальник:

```
FLIGHT_PROVIDER=wikiproject
WIKIPROJECT_ENDPOINT=https://agency.wikiproject.in/
WIKIPROJECT_USERID=<логін від постачальника>
WIKIPROJECT_PASSWORD=<пароль від постачальника>
WIKIPROJECT_METAID=2023
WIKIPROJECT_WEBSITE=<домен, під яким вас завели>
WIKIPROJECT_CURRENCY=USD
WIKIPROJECT_LIMIT=60
```

Три речі, які варто знати про цей ендпоінт, бо вони незвичні:

1. **Логін і пароль ідуть у самому URL**, не в заголовку. Так влаштований
   постачальник, не ми. Тому ці значення не можна світити в логах і не можна
   класти в git — адаптер їх затирає у всіх повідомленнях про помилки
   (`redact()` у `src/providers/wikiproject.js`).
2. **Помилки приходять із кодом 200.** Неправильний пароль виглядає як успішна
   відповідь, поки не прочитаєш тіло: `{"message":"Invalid userid or password"}`.
   Перевіряти сам лише HTTP-статус тут недостатньо.
3. **Параметр `limit` приймається й ігнорується.** Скільки не проси, повертає
   всі 700 оферів (1.7 МБ). Обрізаємо на своєму боці — вже після сортування за
   ціною, щоб лишались найдешевші, а не випадковий шматок.

Класи обслуговування мапляться так: `Y` економ, `S` преміум-економ,
`B` бізнес, `F` перший.

### Варіант B — Duffel (більше не рекомендований)

Залишено в коді як робочий запасний варіант.
Перевірений на живому API.

1. Зареєструватися на https://duffel.com
2. Увімкнути **Developer test mode** (перемикач у дашборді).
3. **Developers → Access tokens → New token**, scope **Read and write**.
4. У `.env`:

```dotenv
FLIGHT_PROVIDER=duffel
DUFFEL_ACCESS_TOKEN=duffel_test_ваш_ключ_сюди
```

Тестові токени починаються з `duffel_test_` і працюють лише з тестовим
контентом Duffel. Бойові — з `duffel_live_`.

Важливо про валюту: Duffel ігнорує `CURRENCY` і віддає ціни у **валюті вашої
організації** — вона міняється в дашборді Duffel, не тут. Інтерфейс показує ту
валюту, яка прийшла разом із пропозицією.

Пропозиції Duffel «протухають» приблизно за 30 хвилин. Коли відкривається
сторінка бронювання, ціна перезапитується через `GET /air/offers/{id}`.

### Варіант C — TripJack (публічне NDC API, не те, що дав клієнт)

Партнерський B2B API. Ключ видає TripJack після договору — самостійно
зареєструватися не можна.

```dotenv
FLIGHT_PROVIDER=tripjack
TRIPJACK_API_KEY=ваш_ключ_сюди
TRIPJACK_BASE_URL=https://apitest.tripjack.com
TRIPJACK_FX_DIVISOR=61.43
```

Для бойового середовища замінити `TRIPJACK_BASE_URL` на продакшн-адресу, яку
дасть TripJack. Ціни приходять в індійських рупіях і діляться на
`TRIPJACK_FX_DIVISOR` (оригінальний сайт жорстко використовує 61.43 для CAD).

Адаптер написаний за публічною документацією і **не перевірявся на живому
ключі** — звірте кілька полів із документацією, коли отримаєте доступ.

### Варіант D — Amadeus (не працює)

Портал Amadeus Self-Service **закрито 17 липня 2026 року**, ключі
деактивовано. Файл `src/providers/amadeus.js` залишений у коді як зразок.
Залишився тільки Amadeus Enterprise / AQC, а він має інші ендпоінти, тож
адаптер довелося б переписувати. Не використовуйте цей варіант.

### Обов'язково для бойового запуску

```dotenv
SESSION_SECRET=довгий_випадковий_рядок
```

Сесія зберігається у підписаному cookie (`src/session.js`). Без власного
секрету підпис можна підробити. Згенерувати:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### Інші корисні змінні

| Змінна | Що робить | Типове значення |
|---|---|---|
| `PORT` | порт локального сервера | `3000` |
| `CURRENCY` | валюта показу | `CAD` |
| `MAX_RESULTS` | стеля кількості пропозицій | `250` |
| `DUFFEL_LIMIT` | скільки найдешевших тягнути з Duffel | `100` |
| `DEFAULT_ORIGIN` | IATA-код для автопідстановки міста вильоту | порожньо |
| `SITE_NAME`, `SITE_LEGAL`, `SITE_DOMAIN`, `SITE_EMAIL`, `SITE_PHONE*` | весь бренд, див. розділ 7 | `.env.example` |

Повний перелік із коментарями — у `.env.example`.

## 3. Розгортання на Vercel

### Головне, що треба розуміти

Файл `.env` **не деплоїться** — він у `.vercelignore`. На Vercel змінні
середовища задаються окремо, у налаштуваннях проєкту. Якщо цього не зробити,
сайт піде в `mock` і показуватиме вигадані рейси.

### Через CLI

```bash
npm i -g vercel
vercel login
vercel link
```

Далі задати змінні (кожну команда спитає значення):

```bash
vercel env add FLIGHT_PROVIDER production
vercel env add DUFFEL_ACCESS_TOKEN production
vercel env add SESSION_SECRET production
```

І викотити:

```bash
vercel deploy --prod
```

### Через вебінтерфейс

1. https://vercel.com → **Add New → Project** → завантажити папку або
   підключити git-репозиторій.
2. **Settings → Environment Variables** → додати `FLIGHT_PROVIDER`,
   `DUFFEL_ACCESS_TOKEN`, `SESSION_SECRET` для оточення **Production**.
3. **Deployments → Redeploy** — змінні підхоплюються лише новим деплоєм,
   наявний не перечитує їх.

### Що вже налаштовано в репозиторії

`vercel.json` перенаправляє всі запити на serverless-функцію `api/index.js`,
яка піднімає той самий Express-застосунок:

```json
{
  "functions": { "api/index.js": { "memory": 1024, "maxDuration": 30, "includeFiles": "pages/**" } },
  "rewrites": [{ "source": "/(.*)", "destination": "/api/index" }]
}
```

Нічого міняти не треба.

### Кешування статики на Vercel

Усі запити переписуються у функцію `api/index.js`, тому заголовок
`Cache-Control`, який ставить сам застосунок, до браузера не доходить — Vercel
замінює його на `max-age=0, must-revalidate`. Без правил у `vercel.json` це
означає, що на кожен перегляд сторінки заново тягнеться і таблиця стилів, і
кожна фотографія.

Тому в `vercel.json` є блок `headers`: тиждень для CSS, JS і шрифтів, місяць
для картинок. Це безпечно, бо в іменах файлів є або хеш вмісту, або `?v=`,
який змінюється разом із файлом. Якщо міняєте CSS — не забудьте підняти
номер версії (розділ 6), інакше тиждень віддаватиметься стара таблиця.

### Обмеження serverless

Заявки й бронювання пишуться у `data/leads/` та `data/bookings/` звичайними
JSON-файлами. На Vercel файлова система **тимчасова**: записане зникає після
завершення функції. Для бойового прийому заявок підключіть базу або зовнішній
сервіс у `src/store.js`. Для демо це не критично.

## 4. Розгортання будь-де ще

Це звичайний Express-застосунок, окремої збірки немає.

```bash
npm install --omit=dev
NODE_ENV=production node server.js
```

Слухає `PORT` (типово 3000). Підходить будь-що: VPS із `pm2`, Docker,
Railway, Render, Fly.io. На відміну від Vercel, там файлова система постійна,
тож заявки в `data/` збережуться.

Приклад для `pm2`:

```bash
pm2 start server.js --name xtremefares --env production
```

## 6. Якщо міняєте стилі

Уся верстка сайту живе в **одному файлі** — `public/assets/css/app.css`,
близько 1 300 рядків. До v5 їх було 28 574 у шести таблицях, які сперечались
між собою через 2 065 `!important`; саме тому кожна правка десь вилазила
деінде. Тих файлів більше немає.

Правила, за якими написаний `app.css`:

- **жодного `!important`**, окрім випадків, коли треба перебити інлайновий
  `style=""`, який пише чужий скрипт (таких місць два, обидва підписані);
- **жодних фіксованих ширин** на тому, що тримає контент — контейнери плинні
  з максимумом, тому стискаються замість того, щоб вилазити;
- **жодних від'ємних маржів** для позиціонування;
- колір, відступи, радіуси й тіні — тільки з токенів на початку файлу;
- mobile first: базовий стан — вузький екран, медіазапити тільки додають.

Хочете змінити фірмові кольори чи шрифти — це блок `:root` у самому верху
`app.css`, там чотирнадцять змінних.

### Версія в посиланнях

Посилання на CSS у `pages/*.html` мають версію: `?v=31`. Це не косметика — у
продакшені файл віддається з річним кешем, тому без зміни номера постійний
відвідувач отримає стару таблицю під новою розміткою.

Змінили CSS — підніміть номер у всіх сторінках:

```bash
sed -i '' 's|?v=31|?v=32|g' pages/*.html pages/*/*.html
```

(на Linux — `sed -i` без `''`)

Локально цього робити не треба: поза `NODE_ENV=production` сервер віддає
статику з `Cache-Control: no-cache`, тож правки видно одразу.

### Де що лежить

| Файл | Призначення |
|---|---|
| `public/assets/css/app.css` | **уся верстка й айдентика сайту** |
| `public/assets/css/fonts.css` | самохостингові шрифти DM Sans і Fraunces |

### Візуальна перевірка

```bash
npm install --no-save puppeteer
node tools/shots.js
```

Кладе знімки в `.shots/`: головна, картка пошуку, футер, і окремо ті стани,
які видно лише після кліку — панель пасажирів, календар, автопідказка
аеропортів. Для бойового сайту: `BASE_URL=https://... node tools/shots.js`.

Чому це окремий крок, а не «та й так видно». Перевірка замірами (чи нічого не
вилазить за межі, чи все вміщається) проходила на всіх 40 сторінках і шести
ширинах — а панель пасажирів при цьому була зламана: вона лежала **всередині**
свого поля й була вужчою за нього, тож формально все сходилось. А ті панелі,
що приховані до кліку, взагалі не потрапляли в перевірку, бо вона відсіювала
невидиме. Заміри й знімки ловлять різні класи помилок; потрібні обидва.

### Чого не можна чіпати в розмітці

`public/ajax/search.js` — 119 КБ успадкованого коду, який ми свідомо не
переписували. Він чіпляється за конкретні `id`, `name` і класи в розмітці:
106 гачків, 1 928 прив'язок на 40 сторінках. Заберете один — бронювання
зламається мовчки: сторінка намалюється, форма виглядатиме правильно, а
календар просто не відкриється.

Щоб це не сталось непомітно, є тест:

```bash
node tests/contract.test.js
```

Він звіряє розмітку зі зліпком `tests/dom-contract.json`. Перезнімати зліпок
(`--record`) можна лише коли ви **свідомо** прибрали якусь функцію — але не
для того, щоб червоний тест став зеленим.


## 7. Ребрендинг: тепер це одне місце

У v3 назва, домен, пошта, телефони й соцмережі більше не зашиті в HTML.
Сторінки містять плейсхолдери `{{SITE_NAME}}`, `{{SITE_EMAIL}}`,
`{{SITE_PHONE}}` тощо, які сервер підставляє з `.env` на кожному запиті.
633 місця замінено на 13 змінних.

Щоб перейменувати бізнес, достатньо цього:

```dotenv
SITE_NAME=Northwind Air
SITE_LEGAL=Northwind Air Inc.
SITE_DOMAIN=northwind.example
SITE_URL=https://northwind.example
SITE_EMAIL=hello@northwind.example
SITE_PHONE=+18005550111
```

Змінилось разом із назвою:

- **Логотип.** Це живий текст, а не картинка: `<span class="brandmark">{{SITE_NAME}}</span>`
  у шапці, попапі та на сторінках бронювання. Стиль — `.brandmark` у `theme.css`.
  Старий бітмап `travel-logo.png` видалено, застаріти більше нічому.
- **Фавікон** і `apple-touch-icon` перемальовані в новій палітрі,
  лежать у `public/assets/images/`.
- **Фото агента** у блоці «Talk to a booking agent» — інше, не те, що було
  в оригіналі: `public/assets/images/agent.bf4ac55b.jpg`, CC0. Джерело — у `CREDITS.md`.
- **Номер телефону** показується у вигляді `1-844-455-5252`, а в `tel:`
  іде як `+18444555252`. Форматує `prettyPhone()` у `src/templates.js`,
  задавати треба лише один формат.

## 8. Що обов'язково перевірити перед запуском

Це не косметика, а речі, за які відповідає власник сайту.

### Юридичні сторінки — замінити

`pages/privacy.html`, `terms-condition.html`, `cookie.html`,
`refund-cancellation.html` містять **юридичний текст оригінального
оператора**. Він навмисно не переписувався: переказувати чужі умови
своїми словами гірше, ніж лишити як є, бо так легко змінити зміст
зобов'язань і не помітити.

Ці чотири сторінки треба замінити текстом, який підготує ваш юрист.

### Тарифи — поставити свої

`pages/charges-fees.html` містить прайс post-ticketing зборів оригінального
оператора ($25, $100, $200, $250, $300). Це комерційні умови чужого бізнесу.
Поставте власні суми або приберіть сторінку.

Там же: `src/pricing.js` додає до кожного бронювання `CONVENIENCE_FEE = 10`.
Це видно клієнту в рядку «Convenience Fee». Файл написаний так, щоб схему
було легко змінити на відсоток, збір з пасажира або нуль.

### Обіцянки на сторінці бронювання

В оригіналі там стояли «IATA Accredited Agent», «Best Price Guarantee»,
«Over 150 Travel Experts» і «100% Secure Guaranteed». Це твердження, які
конкретний бізнес або має право робити, або ні. Їх замінено на нейтральні:
«Secure card payment», «Full price breakdown before you pay», «Agents on
the phone, any hour», «Changes handled by a person, not a form».

Якщо ви справді акредитовані в IATA або даєте гарантію ціни — поверніть
формулювання в `pages/airline/booking.html` і `returnbooking.html`.

### Незакриті теги в розмітці

Сторінки, успадковані з оригіналу, мають незбалансовані теги: `</footer>`
немає на жодній із 40 сторінок, плюс по кілька зайвих `</span>` і `</div>`.
Браузери це мовчки виправляють, і сайт рендериться однаково, але валідатор
свариться. Це дефект джерела, а не наслідок переробки — той самий стан
у першому коміті репозиторію.

Наслідок на практиці один: банер про cookie технічно лежить усередині
`<footer>`, тому правила `footer a` в `theme.css` діють і на нього.

### Зображення

Усі фото напрямків і турів замінено на ліцензійно чисті з Wikimedia Commons —
дев'ять CC0 або суспільне надбання, шість CC BY. Перелік із авторами, ліцензіями
і посиланнями — у `CREDITS.md` у корені.

Шість файлів під CC BY **вимагають зазначення авторства**. Найпростіше — сторінка
джерел із таблицею з `CREDITS.md` і посиланням на неї у футері.

#### Про спрайти — історична довідка

До v5 картки напрямків малювались не тегом `<img>`, а фоном зі **спрайта**:
однієї великої склейки, з якої кожна картка показувала свій шматок. Теги
`<img>` у розмітці були, але їх ховало правило `display: none`. Через це
заміна файлу, на який вказував `<img>`, нічого не міняла на сторінці: за
прямим посиланням лежало нове фото, а на сайті лишалось старе.

**У v5 цього немає.** Таблиці стилів, які створювали спрайти, видалені разом
із самими склейками (`spirit-img-1.png`, `spirit-img-2.png`). Картинки — це
звичайні `<img>`, міняються правкою `src` у сторінці. Прихованих шарів немає.

### Бренд, адреса й телефони

Сайт більше не носить назву оригіналу. Дані клієнта (бриф + задача ClickUp, 28.09):

| | |
|---|---|
| назва | Flights Monkey |
| юридична назва | Flights Monkey LLC |
| адреса | 7900 N Stadium Drive, Houston, TX 77030 |
| EIN | 99-4660195 |
| домен | reservationsflightstoday.com (клієнт його купив) |
| ринок | США, англійська |

Усе це задається в `.env` і підставляється в сторінки: назва — у 137 місць,
пошта — у 132, юридична назва — у 40. Адреса стоїть у футері всіх сторінок і на
`/contact`; EIN — поруч із юридичною назвою в рядку © у футері й на `/contact`.
Міняється одним рядком, правити HTML не треба. Без змінних на сервері (як зараз
на Vercel) діють значення за замовчуванням із `src/config.js` — ті самі дані.

**Телефони — заглушка, клієнт впише сам.** Справжніх номерів клієнт не дав;
28.09 у задачі домовились лишити «рибу». Стоїть `+11111111111` (на сторінках
показується як `1-111-111-1111`): на відміну від попереднього `1-800-555-0100`,
його неможливо сплутати зі справжньою лінією. Що вписати:

- `SITE_PHONE` — основний номер: `/contact`, FAQ, футер, блоки й попапи
  «зателефонуйте нам»;
- `SITE_PHONE_ALT` — окремий номер сторінки `/alaska-flights`, якщо не задано,
  береться `SITE_PHONE`;
- `SITE_PHONE_2`, `SITE_PHONE_3` — другий і третій рядок телефону у футері;
  порожні, тож рядків не видно. Задасте номер — рядок з'явиться сам.

Раніше тут стояли чотири **справжні номери xtremefares.com**; віддавати їх
клієнту було не можна, тому їх і замінили.

**Посилання.** У брифі поле Links порожнє, у переписці — «Sam will tell».
Соцмереж у клієнта немає, тож зовнішніх посилань на сайті немає. Якщо клієнт
захоче якісь додати, треба знати, куди саме вони мають вести.

**Соцмережі прибрані повністю** — клієнт відповів, що акаунтів не має й не
бачить потреби. Пішли не лише іконки, а й блок «Follow Us» з обох футерів на
всіх 40 сторінках, змінні `SOCIAL_*` з конфігу й `.env`.

### Логотип

Клієнт свого лого не має: «No specific logo, use as per the best». Тому знак
намальований під назву — `public/assets/images/logo-mark.svg`. Ідея одна:
хвіст мавпи й траєкторія зльоту — та сама крива. Вона скручується внизу
плитки й випрямляється в набір висоти, літак стоїть у точці, де виток
відпускає.

Один файл на все: шапка, футер і фавікон беруть його ж. Підключений через
`.brandmark::before` у `app.css`, тому розмітка сторінок не чіпається.

### Тексти

Маркетингові тексти переписані з нуля в v3: головна, «про нас», контакти,
FAQ, сторінки напрямків і турів. Свідомо **не** використано вигаданих
метрик на кшталт «відповідаємо за 5 секунд» або «час очікування 5 секунд» —
це обіцянки, яких ніхто не давав. Якщо у вас є реальні цифри, додайте їх.
